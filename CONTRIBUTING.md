# Contributing

## Prerequisites — two paths, pick one

This repo touches four language ecosystems (TypeScript, Rust, Solidity, Python), and
each one needs both "the right library versions" (a lockfile) and "the right tool
itself installed" (a runtime). Lockfiles are committed and require no action from you.
Runtimes are not automatically available on a fresh machine — pick one of the two paths
below to get them.

### Path A — Dev Container (recommended, zero local installs)

Requires only [Docker](https://www.docker.com/) and, if using VS Code, the
[Dev Containers extension](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-containers).
Open the repo, accept the "Reopen in Container" prompt (or run
**Dev Containers: Reopen in Container** from the command palette). Node, pnpm, Rust,
the wasm32 target, wasm-pack, Foundry and Python all arrive pre-installed at the
versions pinned in [`.devcontainer/`](.devcontainer/devcontainer.json), and Anvil,
PostgreSQL and Redis start automatically as sibling containers. Nothing to install,
search for, or troubleshoot beyond Docker itself.

### Path B — Local install

Each tool has its own pin file; the tool itself still needs installing once, by hand.

```bash
# Node — corepack reads package.json's "packageManager" field
corepack enable
nvm use                  # reads .nvmrc

# Rust — rustup reads packages/pq-core/native/rust-toolchain.toml automatically
# once you're in that directory; install rustup itself first if you don't have it:
# https://rustup.rs
rustup target add wasm32-unknown-unknown
cargo install wasm-pack --locked

# Foundry — same command CI runs (see .github/workflows/ci.yml), stable channel
curl -L https://foundry.paradigm.xyz | bash
foundryup

# Python (only needed for eval/, M11) — see eval/README.md
```

If you're not sure which path to pick: Path A. It's the only one of the two that
actually delivers "a colleague clones this and never has to install or debug a
missing tool" — Path B still requires each of the four commands above to succeed on
whatever OS your colleague happens to be running.

## What guarantees a clean clone actually works

Two different guarantees, and both are needed:

| Ecosystem | Pins *which library versions* | Pins *which tool/runtime version* |
| --------- | ------------------------------ | ---------------------------------- |
| Node/TS   | `pnpm-lock.yaml`                | `.nvmrc` + `packageManager` in `package.json` |
| Rust      | `Cargo.lock` (once `pq-core` has code) | `packages/pq-core/native/rust-toolchain.toml` |
| Solidity  | `contracts/lib/` pinned commits | `version: stable` in CI + `foundryup` locally |
| Python    | `eval/requirements.txt` (generated by `pip freeze`, never hand-edited) | a `venv`, isolating this project from your global Python |

A lockfile alone doesn't help if the runtime itself is missing — that's what the Dev
Container in Path A collapses into a single "have Docker" requirement. See
[`.devcontainer/devcontainer.json`](.devcontainer/devcontainer.json) and
[`eval/README.md`](eval/README.md) for more on each.

## Clean-clone check

A fresh clone must pass all of these before any work is considered mergeable:

```bash
pnpm install && pnpm lint && pnpm typecheck && pnpm build && pnpm test
```

## Branching

Trunk-based development with feature flags. With three developers on one contract
surface, merge debt is the dominant schedule risk, so branches are short-lived and
incomplete work ships behind a flag in `.env` rather than living on a long branch.

- Branch from `main`, merge back to `main`. No long-running integration branches.
- Two approvals required to merge.
- Contract changes must additionally pass the invariant suite in CI.

## Commit convention

[Conventional Commits](https://www.conventionalcommits.org/):

```
feat(m4): add virtual-share offset to AssetVault
fix(m2): reject envelopes whose nonce equals stored value
chore(m0): pin pnpm via corepack
docs(adr): record Arbitrum L2 platform choice
test(m7): invariant — every liquidation strictly increases HF
```

Scope is the module identifier (`m0`–`m11`) where one applies.

## Interfaces before implementations

A module is admitted only if its interface can be written before its implementation,
its dependency set is acyclic, and its acceptance test is runnable by a third party.

Each module therefore opens with a pull request containing **only its interface and
invariants**, approved by the consumers of that interface, before any implementation is
written. This is what keeps three developers from blocking on each other.

## Architecture decision records

Any decision a reviewer would reasonably ask "why this way?" about needs an ADR in
`docs/adr/`. See [ADR 0001](docs/adr/0001-record-format.md) for the format. ADRs are
immutable once accepted — supersede, never edit.

## Repository layout

| Path            | Contents                                                                  |
| --------------- | ------------------------------------------------------------------------- |
| `packages/`     | Shared libraries. Consumed by `apps/` and `services/`, never the reverse. |
| `services/`     | Backend services (NestJS / Node workers).                                 |
| `apps/`         | User-facing clients.                                                      |
| `contracts/`    | Foundry project. Outside the pnpm workspace — own toolchain.              |
| `eval/`         | Python evaluation harness (M11) — own venv, see `eval/README.md`.         |
| `infra/`        | Docker Compose devnet (Anvil, PostgreSQL, Redis).                         |
| `.devcontainer/`| Dev Container — the zero-local-install setup path (see Prerequisites).    |
| `docs/adr/`     | Architecture decision records.                                            |

Dependency direction is one-way and enforced by review: if a package ever needs to
import from a service or an app, the shared piece belongs in `packages/` instead.
