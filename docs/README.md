# Documentation

This folder is the documentation root. It separates **deliverables** (documents
submitted or presented to the supervisor and the evaluation panel) from the
**engineering record** (decisions, architecture and stage reports) that the
codebase is built against.

Only the current revision of each deliverable is kept in the tree. Superseded
revisions stay in git history, and every deliverable can be regenerated from the
`source/` folder beside it.

## Layout

```
docs/
├── deliverables/     Supervisor- and panel-facing documents (current revision only)
│   ├── proposal/     IEEE technical proposal + generator sources
│   └── presentation/ Proposal defense deck, script, technical guide + generator sources
├── manuals/          Build plan and per-module engineering manuals
├── reports/          Stage reports and task breakdowns
├── adr/              Architecture decision records, immutable once accepted
├── architecture/     System blueprint and the Mermaid sources for the FigJam maps
└── linkedin-assets/  Images for public posts
```

## Conventions

- **One current revision.** Replace a deliverable in place rather than adding a
  `_v4` beside it; git history is the version record.
- **Sources travel with the document.** Anything generated keeps its generator
  and assets in the `source/` folder next to the output.
- **Naming.** Deliverables and manuals are prefixed `QORA_`; reports and ADRs
  use lowercase kebab-case.
- **No build output.** PowerPoint autosaves, Word lock files (`~$*`) and page
  renders are ignored by git and must not be committed.
- Markdown here is formatted with Prettier, which CI checks.
