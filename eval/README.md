# M11 — Evaluation harness (Python)

Processes Foundry gas snapshots and k6 output into the RQ1–RQ4 tables and figures for
the thesis (proposal §VII). This is the one part of the stack that isn't TypeScript or
Solidity, so it gets its own isolated Python environment rather than depending on
whatever happens to be installed globally on a developer's machine.

## Why a venv, and not something else

A **virtual environment** is a self-contained copy of the Python interpreter and its
`site-packages` directory, scoped to this project only. It solves exactly the problem
`node_modules/` solves for Node: without it, `pip install pandas` installs into the one
global Python on your machine, shared by every other Python project you have — so two
projects wanting different pandas versions collide, and there is no lockfile-equivalent
telling a colleague what "the right global state" even was.

`venv` ships with Python itself (3.3+), so this needs **no new tool** beyond Python,
which is already required to run anything here.

## Setup

```bash
cd eval
python -m venv .venv

# Activate (pick your shell):
source .venv/bin/activate          # macOS / Linux / Git Bash on Windows
.venv\Scripts\Activate.ps1         # Windows PowerShell

pip install -r requirements.txt    # exact, reproducible versions
```

`requirements.txt` is the lockfile — generated by `pip freeze`, never hand-edited. It's
committed to git, so `pip install -r requirements.txt` reproduces the identical
dependency set on any machine, the same guarantee `pnpm install --frozen-lockfile`
gives on the Node side.

`requirements.in` is the human-edited *intent* file. Add a package there, then
regenerate the lock:

```bash
pip install -r requirements.in
pip freeze > requirements.txt
```

## Layout

```
eval/
  requirements.in     human-edited dependency intent
  requirements.txt    generated lock (pip freeze) — committed, reproducible
  scripts/            RQ1-RQ4 data processing (gas curves, break-even n*, Monte Carlo)
  notebooks/          exploratory analysis, not part of the reproducible pipeline
```

Reproduction scripts (the ones cited in the thesis) belong in `scripts/`, as plain
`.py` files runnable non-interactively — notebooks are for exploration, not for the
artefact a reader would run to reproduce a figure.
