# 🧭 T5.1 — `DeployM3.s.sol`: deploy spec

**For the [[Coder Agent]].** One `forge script` that deploys and wires the whole M3 suite for **one asset** (ADR 0016)
and writes the addresses where T6.1a, T6.1b and How to Run can read them. Inherited: ADR 0015 (owner = multisig,
agent = Tier 1 key, trust-basis setters behind the owner), ADR 0025 (plain constructor deploys, no proxies),
ADR 0018 (τ = 24 h default, configurable), Q23 (onchain-id via `vm.deployCode`).

## 1. Inputs: environment only, never hardcoded

| Variable | Meaning | Default |
| -------- | ------- | ------- |
| `M3_OWNER` | owner of every M3 contract (the multisig) | **required** |
| `M3_AGENT` | Tier 1 service key: agent on token, identity registry and asset registry; submitter on the source | **required** |
| `M3_KYC_ISSUER_KEY` | management + claim key of the project KYC `ClaimIssuer` (Q3) | **required** |
| `M3_ASSET_REF` | the slug, e.g. `gold-lot-001` | **required** |
| `M3_TOKEN_NAME` / `M3_TOKEN_SYMBOL` | e.g. `QORA Gold Lot 001` / `qXAU-001` | **required** |
| `M3_VALUATION_WINDOW` | global τ in seconds | `86400` (ADR 0018) |
| `M3_IDENTITY_STORAGE` | reuse an existing shared `IdentityRegistryStorage` (ADR 0016) | unset = deploy a new one |

**Owner safety:** on any chain other than anvil (`block.chainid != 31337`), `M3_OWNER` must have code, or the script
reverts `OwnerMustBeContract(owner)`. On anvil an EOA owner is allowed, with a loud log line:
`OWNER IS AN EOA — local only, not ADR 0015 conformant`. The real 2-of-3 multisig is T5.2.

## 2. Order (each line is one step; the comment says who sends it)

```
1  ctr  = new ClaimTopicsRegistry(OWNER);              ctr.addClaimTopic(KYC_TOPIC)          // owner
2  kyc  = deployCode(onchain-id ClaimIssuer, KYC_ISSUER_KEY); kyc.addKey(keccak(KYC_ISSUER_KEY), 3, 1) // issuer key
3  tir  = new TrustedIssuersRegistry(OWNER);           tir.addTrustedIssuer(kyc, [KYC_TOPIC]) // owner
4  irs  = M3_IDENTITY_STORAGE or new IdentityRegistryStorage(OWNER)
5  ir   = new IdentityRegistry(OWNER, tir, ctr, irs);  irs.bindIdentityRegistry(ir); ir.addAgent(AGENT) // owner
6  ar   = new AssetRegistry(OWNER);                    ar.addAgent(AGENT); ar.setValuationWindow(WINDOW) // owner
7  src  = new CustodianAttestationSource(OWNER);       src.addSubmitter(AGENT); ar.setAttestationSource(src) // owner
8  mc   = new ModularCompliance(OWNER);  mod = new AssetLiveModule(ar);  mc.addModule(mod)     // owner
9  tok  = new Token(OWNER, ir, mc, NAME, SYMBOL, address(0))   // binds mc in its constructor; deployed paused
         tok.addAgent(AGENT); ir.addAgent(tok)                  // owner (token as IR agent: recoveryAddress, T3 §5)
10 (not in T5.1: register + setTokenFor happen at onboarding, see §3)
11 (not in T5.1)
12 tok.unpause()                                                 // agent, last
13 _verifyWiring();  _writeDeployment();
```

Steps 1, 3 and 5 to 9 need the owner key, step 12 the agent key, and step 2 the issuer key. The script uses
`vm.startBroadcast(<key>)` per role, with keys from `--private-keys` / env (`M3_OWNER_PK`, `M3_AGENT_PK`,
`M3_KYC_ISSUER_PK`). **No key in any committed file** (same rule as T6.0 AC-3). When `M3_OWNER_PK` is absent
(multisig on a real chain), the script still deploys every contract (constructors only take addresses), then prints the
owner calls from steps 1, 3 and 5 to 9 as `to / data` pairs for the multisig to sign. It never fakes them.

## 3. Register at deploy, or at onboarding? Ruling: **at onboarding. T5.1 stops before step 10 by default.**

`setTokenFor` requires the asset to be registered (T4.1, per the interface), and `register` commits `metadataHash`,
which is computed from the **onboarding input** (T6.0 `METADATA_HASH_FIELDS`). Registering at deploy would commit a
hash before the provider's input exists, permanently (ADR 0019 §1: nothing un-registers). So:
- **T5.1 (default):** steps 1 to 9, then 12 (unpause), 13. The token exists but is bound to no asset. Its mints fail
  closed, because `assetOfToken` returns 0 and the module returns false (T0.6 Fix Spec §5.1).
- **T6.1a** (this is steps 10 and 11): `register(assetId, metadataHash(input), slug)` (agent) → the **owner** binds with
  `setTokenFor(assetId, token)` → submit + `admit` → `mint`. On anvil T6.1a can send the owner step itself. On a real
  chain it prints the calldata and waits, which T6.2's protocol covers as a named pause.
- **T5.3 smoke** (`--sig "smoke()"`, anvil only) does the full chain with a FIXTURE lot so CI proves the wiring end
  to end. Its fixture `source` string is marked FIXTURE (T6 spec §9.1), and it never runs off anvil
  (`SmokeIsLocalOnly()`).

## 4. `_verifyWiring()`: the script checks itself

Revert `WiringMismatch(string what)` unless all of these hold: `tok.identityRegistry() == ir`, `tok.compliance() ==
mc`, `mc.getTokenBound() == tok` (covers the bindToken squat, T2 rulings), `mc.isModuleBound(mod)`,
`ir.identityStorage() == irs`, `ir.issuersRegistry() == tir`, `ir.topicsRegistry() == ctr`,
`ctr.getClaimTopics() == [KYC_TOPIC]`, `tir.hasClaimTopic(kyc, KYC_TOPIC)`, `ar.attestationSource() == src`,
`ar.valuationWindowOf(0) == WINDOW`, `ar.isAgent(AGENT)`, `tok.isAgent(AGENT)`, `ir.isAgent(AGENT)`,
`ir.isAgent(tok)`, `src.isSubmitter(AGENT)`, the `owner` of every contract `== OWNER`, and `!tok.paused()`.

## 5. Output

`contracts/deployments/<chainid>.json`, written with `vm.serializeAddress` / `vm.writeJson`:
`{ chainId, owner, agent, kycIssuer, claimTopicsRegistry, trustedIssuersRegistry, identityRegistryStorage,
identityRegistry, assetRegistry, attestationSource, compliance, assetLiveModule, token, assetRef, valuationWindow,
gitCommit }`. `foundry.toml` gains `{ access = "read-write", path = "./deployments" }` in `fs_permissions`.
`deployments/31337.json` is gitignored (it changes every run). Testnet files are committed. T6.1a reads this file and
nothing else to find addresses.

## 6. Tests and acceptance

`contracts/test/script/DeployM3.t.sol` runs `DeployM3.run()` in-process with anvil-style keys and asserts §4 again
from outside, plus `smoke()` ending with the asset LIVE and `totalSupply == intendedSupply ≤ reserveOf`.

- **AC-T5-1** On a fresh `anvil`, `forge script script/DeployM3.s.sol --rpc-url local --broadcast` exits 0 and writes
  `deployments/31337.json`. A re-read with `cast call` of `token.compliance()` and `assetRegistry.attestationSource()`
  matches the file.
- **AC-T5-2** `DeployM3.t.sol` passes, including `test_SmokeOnboardsFixtureLot` and
  `test_WiringCheckCatchesSquattedCompliance` (a pre-bound compliance reverts `WiringMismatch("compliance.token")`).
- **AC-T5-3** `test_RejectsEoaOwnerOffAnvil` (`vm.chainId(421614)`, EOA owner → `OwnerMustBeContract`).
- **AC-T5-4** `grep -rn "PRIVATE_KEY\|0x[0-9a-f]\{64\}" contracts/script` finds no literal key.
- **AC-T5-5** How to Run §6 is updated to the real commands and env names (the Researcher checks it against the
  script).
