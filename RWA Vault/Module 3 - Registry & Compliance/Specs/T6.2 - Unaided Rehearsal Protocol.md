# 🧭 T6.2 — Unaided onboarding rehearsal: the protocol

**What this proves:** M3's done-sentence, *"a provider onboards a gold lot unaided"*. Someone who wrote none of T6
takes a gold lot from a sheet of paper to a LIVE asset with minted tokens, using only the written docs. Every time
they have to ask, guess or wait, that is a defect **in the docs**, never in the person. Source:
[[Specs/T6 - Provider Onboarding Console]] §5 and AC-15/16, and [[Questions/Q22 - Who runs the T6.2 unaided onboarding rehearsal|Q22]] = A.

## 1. People

| Role | Who | May they speak? |
| ---- | --- | --------------- |
| **Participant** | Hassan or Fawaz, whichever authored **none** of T6.0, T6.1a or T6.1b (Q22) | Yes, aloud. Thinking aloud helps the recorder |
| **Recorder** | anyone except the participant | Only the two fixed lines in §4 |
| **Author** (the T6 implementer) | may watch | **No.** Any word to the participant is an intervention, and the run fails |

## 2. Before the session (the recorder prepares; the participant sees none of it until the clock starts)

1. **Pin the commit.** `git rev-parse HEAD` of the branch under test, with T5.1 and T6.1a green in CI at that SHA.
   Write it on the report.
2. **The lot sheet** (one printed page, what a real provider would hand over): asset name `gold-lot-002`, a
   description, gross weight `1000 g`, fineness `999.9`, custodian id, provider wallet address, and the valuation
   basis marked **FIXTURE**. It is a second lot on purpose, so the committed `gold-lot-001` example cannot be copied
   blindly.
3. **Two envelopes**: `att.gold-lot-002.seq1.cbor` (fresh) and `att.gold-lot-002.STALE.cbor` (valuation older than
   τ). They are labelled only "envelope A" and "envelope B". The participant is handed **B first** (see §3, S7).
4. **A clean machine or account:** no existing clone, no `~/.foundry` from the author, no shell history.
5. **Docs given:** the repo README and [[Running/How to Run Module 3]]. Nothing else. No chat and no notes from the
   author.

## 3. The run (the clock starts at S0; the recorder writes the wall time at every step)

| Step | The participant… | Expected end state |
| ---- | ---------------- | ------------------ |
| S0 | clones the repo at the pinned SHA and installs the prerequisites from How to Run | `forge --version` and `pnpm --version` print |
| S1 | builds and runs the tests | `forge test` green |
| S2 | starts a local chain | anvil on :8545 |
| S3 | deploys the suite (T5.1) | `deployments/31337.json` exists |
| S4 | makes the provider wallet KYC-verified (the documented step) | `isVerified(providerWallet) == true` |
| S5 | writes the onboarding JSON for the lot sheet, using the T6.0 schema | the file validates |
| S6 | runs the onboarding script **without** `--broadcast` and reads the pre-flight | pre-flight prints with no error |
| S7 | broadcasts **with envelope B** (stale) | script stops with the `ValuationStale` sentence, which names the envelope's timestamp (AC-19). The asset stays PENDING |
| S8 | recovers **from the message alone** by switching to envelope A and re-running | the script continues from PENDING (idempotent, AC-6) |
| S9 | completes the owner binding step and the admit and mint (on anvil the script sends the owner step itself; T5.1 §3) | receipt: LIVE, `attestedSupply == 999.9e18`, `≤ reserve`, units printed as **fine grams** (AC-23) |
| S10 | confirms on-chain with `cast call` as the docs show | `stateOf == LIVE` (2), supply matches |
| S11 | runs the script once more, unchanged | exits 0, "already live", no second mint |
| S12 | runs the bypass demo from How to Run §7: a direct transfer to an unverified wallet | reverts `ReceiverNotVerified` |

S7 and S8 are the point of the exercise. A stale envelope is the most likely real failure (ADR 0019 rationale (1)),
and the error sentence is the only help a real operator gets.

## 4. What the recorder may say, and what counts as a defect

The recorder says only: **"Please use the docs."** (to any question) and **"Time."** (when ending the run under the
stop rule). Anything else is an intervention.

Log a defect, **against the document**, whenever the participant:
- asks a question (even one the recorder does not answer);
- is stuck with no progress for more than **60 seconds**;
- guesses (says "I think…" and acts on it), or does something the docs did not say to do;
- reaches a wrong end state for a step (e.g. edits the input `valuationTs` in S8 instead of changing the envelope).

| Severity | Meaning |
| -------- | ------- |
| **P0** | Could not finish the step from the docs, needed an intervention, or the chain state ended wrong |
| **P1** | Finished, but only by guessing, or stuck for more than 5 minutes |
| **P2** | Wording, ordering or formatting friction that slowed them without risk |

**Stop rule:** stuck for **10 minutes** on one step → the recorder says "Time.", logs a P0, and the run ends as FAIL.

## 5. Verdict and the loop

- **PASS** = S0 to S12 all reached, **zero interventions**, **zero open P0** (AC-16). Time is recorded but is not a
  gate.
- **FAIL** = anything else. Fix the docs (or the script's sentences) for every P0 and P1. Then **re-run with a
  different participant** if any P0 was found (T6 spec §5). The same person now knows the answers.
- P2s are fixed but do not force a re-run.

## 6a. Recorder's checks after the run (added 2026-10-28)

Paste each command and its output verbatim into the report, under "Post-run checks":

```bash
git log --format='%an' -- contracts/script/OnboardAsset.s.sol apps/ops-console   # participant's name must not appear
ID=$(cast keccak "gold-lot-002")
cast call $ASSET_REGISTRY "stateOf(bytes32)(uint8)" $ID          # 2 (LIVE)
cast call $ASSET_REGISTRY "reserveOf(bytes32)(uint256)" $ID        # R
cast call $TOKEN "totalSupply()(uint256)"                          # S == intendedSupply, S <= R
cast call $TOKEN "balanceOf(address)(uint256)" $PROVIDER_WALLET    # == S (the provider, never the operator; C2)
cast call $ASSET_REGISTRY "metadataHashOf(bytes32)(bytes32)" $ID   # == the hash the script printed
```

The report is created **on the day of the run, not before**. AC-15 only says it "exists", so a skeleton committed early
would pass a check it should not.
