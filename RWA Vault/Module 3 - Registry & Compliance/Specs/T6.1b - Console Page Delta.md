# 🧭 T6.1b — Console page: what changed since T6 spec §4

**No new ADR.** ADR 0026 (Accepted, Q21) already records React 18 + Vite + viem + TanStack Query for
`apps/ops-console`. AC-10 is met by citing it. Do not write 0028 for this. The base spec stays
[[Specs/T6 - Provider Onboarding Console]] §4 with AC-9 to AC-14 and AC-20. This note only lists what T6.1a settled,
which the page must match.

1. **Addresses** come from `contracts/deployments/<chainid>.json`, imported at build time (or chosen by chain id).
   Nothing is hardcoded.
2. **Same validator, same hash.** Step 1 uses `validateOnboardingInput` from `@rwa-vault/types`. `metadataHash` uses
   viem `encodeAbiParameters` with the 8-field recipe in [[Specs/T6.1a - Onboarding Script Spec|T6.1a §3]] and must
   reproduce `GOLD_LOT_001_METADATA_HASH` (component test).
3. **Clause 1 in the browser:** verify the §2.2 fixture attestation with pq-core's **wasm** adapter. Use the same
   message recipe, and take the custodian key from the committed `custodian.mldsa65.pub` checked against
   `custodianKeyHash`. On failure, render the `BadAttestationSig` sentence. The ADR 0017 banner stays non-dismissible
   (AC-12).
4. **Signing:** the operator's Tier 1 agent key through an injected wallet (viem `custom(window.ethereum)`). On chain
   31337 only, an "anvil dev key" option may use a viem local account. **No owner key in the browser.** When
   `tokenOf == 0`, the binding step shows the `setTokenFor` `to / data` for the multisig and a "re-check" button,
   just like T6.1a's exit 2.
5. **State-branch table** is identical to T6.1a §3 S (resume a LIVE asset with zero supply, refuse partial supply,
   refuse FROZEN). The page re-reads `stateOf` from chain on every render (§4.2).
6. **Sentences:** import the T6.1a sentence table from one shared module (`packages/types/src/onboarding-messages.ts`,
   moved out of `run.mjs`) so the script and the page cannot drift. Add a test asserting that both use it.
7. **AC-14 grep** also covers `burn`, `recoveryAddress` and `setAddressFrozen`.
