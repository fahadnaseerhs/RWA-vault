## Part A

### A1 — `assetId` → on-chain id: **keccak256, option (b)**

`bytes32 id = keccak256(bytes(assetId))`.

Agreed with the Coder's recommendation. Right-padding (option a) silently truncates at 32 bytes and makes `"gold-lot-001"` and `"gold-lot-001\0"` different ids that look identical in a log; a `string` key on-chain (option c) costs gas on every lookup for no benefit.

**One requirement that comes with it:** because the hash is unreadable, `AssetRegistered` **must** carry the human slug as a `string` alongside the `bytes32`, or no operator will ever map an event back to a lot. Specified in [[T0.6 - IAssetRegistry Interface]] §3.

Schema unchanged — the 32-byte cap stays for readability and event size, not because the hash needs it.

### A2 — `metadataHash`: **the script computes it, option (a)**

This was a real gap in the research. Closing it now, exactly:

```solidity
metadataHash = keccak256(abi.encode(
    assetId,                      // string  — the slug, not the hash
    description,                  // string
    valuationBasis.source,        // string
    valuationBasis.currency,      // string
    valuationBasis.unitValue,     // uint256 — parsed from the base-10 string
    custodianId                   // string
));
```

`abi.encode`, not `abi.encodePacked` — packed encoding of adjacent dynamic strings is ambiguous (`"ab" + "c"` collides with `"a" + "bc"`), which is exactly the collision an auditor looks for. A third party reproduces this with `viem`'s `encodeAbiParameters` + `keccak256`, so it stays verifiable off-chain.

**Deliberately excluded, and why:**
- `valuationBasis.valuationTs` — changes with every re-attestation; the hash must be stable for the life of the asset.
- `treasuryWallet`, `token` — deployment wiring, not the identity of a gold bar.
- `attestations` — evidence about the asset, not the asset.

Add this to [[Mathematics - Admission Predicate and Invariants]] as §6 so the Debugger and the examiners have one source for it.

### A3 — `custodianId` → on-chain key: **option (b), one global custodian for MS1**

`register` takes **two** arguments only: `(assetId, metadataHash)`. The custodian key lives behind `IReserveAttestationSource` (ADR `0017`), bound once at wiring time (T5.1), not per asset.

`custodianId` therefore stays **informational** in the input — and it is part of `metadataHash` (A2), so it is committed to on-chain even though no function reads it.

**Why not per-asset now:** a per-asset custodian mapping is the same shape as the attestor registry that Q11 would need. Building half of it, for one custodian, is the worst of both. If Q11 = B, an attestor registry replaces this cleanly behind the same seam.

## Part B

### B1 — Two timestamps: **the envelope's wins; the input's is informational**

The chain checks the **envelope's** `valuationTs` in clause 4. Nothing else.

The input's `valuationBasis.valuationTs` documents *when the quoted `unitValue` was taken* and is kept. Neither removal nor forced equality: they genuinely describe different facts (a price quote vs a vault count), and forcing them equal would make the file fail for an honest reason.

**But the Coder's risk is real** — an operator will edit the input file trying to clear a `ValuationStale` revert, and nothing will change. Two concrete requirements fix it:

1. The script prints both timestamps side by side in its pre-flight output, and **warns** (does not abort) when they differ by more than 1 hour.
2. The `ValuationStale` message must name the source: *"The custodian's attestation is H hours old; the limit is τ. This is the timestamp inside the signed envelope — editing the input file will not change it."*

That second sentence is now part of §3.4's table and is checked by **AC-5**. Added as **AC-19** in [[T6 - Provider Onboarding Console]].

### B2 — `unitValue`: **kept, both (a) and (b)**

It is informational for the receipt and the console, **and** an input to `metadataHash` (A2). So it now has a job. No change.

### B3 — `assetId` format: **confirmed**

`^[a-z0-9][a-z0-9-]{0,31}$`. Lowercase-only removes the "was it `Gold-Lot-001`?" class of support question, and with A1 the hash makes case a silent id change rather than a visible typo — worth excluding by construction.

### B4 — `attestor`: **`"custodian"` only**

Do not add `"insurer"` yet. Q11 is undecided, and shipping the enum value would imply a decision Fahad has not taken — and would make a reviewer think the insurer path works. The array (A-shape) is the forward-compat; the enum is not.

When Q11 lands as B, widening is one line in `AttestorRole` plus the schema `enum`, and the threshold logic belongs in the predicate (T4.2), not here.

### B5 — Checksums: **format-only here, enforced downstream**

Correct call, and the reasoning is right: `@rwa-vault/types` must stay dependency-free, and EIP-55 needs keccak.

But "viem will catch it anyway" is not good enough to leave unstated, because it is exactly the kind of assumption that turns out false in one of the two front-ends. So it becomes an explicit requirement rather than a hope:

> **AC-20 (new).** The script (T6.1a) and the console (T6.1b) each reject a mixed-case address that fails its EIP-55 checksum, with a named error that quotes the address. An all-lowercase address is accepted (it carries no checksum to fail).

Added to [[T6 - Provider Onboarding Console]] §6.

### B6 — `attestations[].path`: **schema changes — `path` or `bytesBase64`, exactly one**

The Coder spotted the real problem: a browser has no path. It has a `File` the provider just dragged in. A page that has to invent a fake path to satisfy the shared type would be the shared type failing at its one job.

```ts
export type AttestationRef =
  | { readonly attestor: AttestorRole; readonly path: string }
  | { readonly attestor: AttestorRole; readonly bytesBase64: string };
```

Exactly one of the two, never both, never neither — validated, with its own issue message. `path` stays relative to `contracts/` as documented.

**Why decide this now rather than when T6.1b is built:** this is the same argument as `attestations` being an array from day one. Fixing it later means touching the type, the JSON Schema, the drift test, the script's parser, the page and every fixture. Fixing it now costs one union and two validator branches.
